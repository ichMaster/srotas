## Scope discipline (MISSION §Scope boundaries — binding)

- **Snapshot-only, never live**: all four adapters read a file/directory
  given as a path argument; none opens a network connection or a live
  database handle. `browser_history.py` opens sqlite in `mode=ro`, never the
  browser's live-locked file. Real snapshots gathered this phase (Lumi
  `store.json`, 3 of 5 Chrome profiles) are point-in-time copies made via
  `sqlite3 .backup`/`cp` before any adapter touched them — MISSION decision
  27 clarifies that the *copy step* may be agent-performed without breaking
  the snapshot-only principle.
- **Manual review gate preserved** — `bootstrap.py` writes `candidates.yaml`
  only; no code path in this phase (or any prior one) writes `model.yaml`
  automatically. Folding reviewed candidates in stays the user's hand-edit,
  same as `pending_topics.yaml` → `model.yaml` since phase 0.5.
- **No work-topic filtering added here** — `work: true/false` is extracted
  and carried through merge, but the topic blacklist (config) and any
  filtering-at-collection-time stay out of scope for this phase, per
  ROADMAP §0.7 Out-of-scope.
- **Out-of-scope items untouched**: no daily windows, no segmentation, no
  citation validation, no returned/abandoned signals (all stage 2).
- **No local ML stack** — extraction uses the same Anthropic Haiku-class call
  as feedback classification (0.5), never a local model.

## DoD note — the "reviewed model" sub-clause

ROADMAP §0.7's DoD has two parts: "bootstrap runs over the real sources and
yields a reviewed model of 10–15 nodes" *and* "pytest green." The code and
tests are complete and green (this report). The **real-data run** is
intentionally not part of this report:

- The Lumi snapshot and 3/5 Chrome profile snapshots are already gathered
  (`bootstrap/snapshots/`, gitignored); 2 profiles remain locked by an open
  Chrome (user offered to quit Chrome to unblock them).
- The Claude export (`conversations.json`) requires the user's own
  authenticated claude.ai export — not something this agent can perform.
- A Notion snapshot requires the MCP server (configured in `.mcp.json`,
  loads at next session start) to fetch pages into local Markdown.
- Running `python -m bootstrap.bootstrap` for real spends a paid Haiku call
  and needs the user's explicit go-ahead.
- Its output, `candidates.yaml`, still requires **manual review** before
  anything is hand-moved into `memory/model.yaml` — no code path does this
  automatically (binding, MISSION §Scope boundaries).

None of this blocks the phase or the release — the roadmap phase ships the
*capability*; producing the real reviewed model is a follow-up the user
drives once the remaining snapshots are ready.
