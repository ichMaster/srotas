Phase v0.5 — **Feedback loop, end to end** — is complete. Typing a reaction on a
card and submitting it now closes the whole loop: a Haiku call classifies the
text (with the card's context), the classified reaction shifts the card's
`top_node` weight (or queues a pending topic), every change is journaled with
the original text and item URL, and — on a weight change — the feed re-scores
(free, cached embeddings) and reorders. 102 tests green, ruff clean repo-wide.
**Phase boundary reached — no release performed** (awaiting user review, then
`/release-version 0.5.0`).

### SROTAS-017: Weight delta + events + pending_topics.yaml queue
**Status:** completed · **Commit:** f86aac6
**Files:** core/feedback.py, core/events.py, core/pending_topics.py, core/config.py, config.example.toml, tests/test_feedback_apply.py
- `apply_reaction()` shifts the card's `top_node` weight by the configured
  delta (default +0.05/−0.07), clamped `[0.05, 1.0]`, via `model.set_weight`

  `new_topic` never touches `model.yaml` — new `core/pending_topics.py` queues
  it in `memory/pending_topics.yaml` for manual confirmation.
**Validation:** [x] pytest (11) · [x] ruff · [x] contract (events row: text + URL) · [x] acceptance

## Contracts

- **Events row carries the original text + item URL** for every
  feedback/weight_update change — already a stated contract (ARCHITECTURE
  §Contracts, "model changes are traceable"); this phase is the first to
  exercise it end to end, pinned by SROTAS-017's contract test.
- No schema contracts changed — `events` stays the minimal 5-column shape from
  v0.1; the Item schema is untouched.

## Scope discipline (MISSION §Scope boundaries — binding)

- **No auto-created nodes** — `new_topic` only ever queues in
  `pending_topics.yaml`; confirmation stays a hand-edit, no code path.
- **127.0.0.1 only** — `/feedback` inherits the app's existing bind.
- No conversational feedback / Lili integration (stage 4) pulled in early.
