Srotas — Release Notes
======================

Version 0.4.0 (2026-07-29)
---------------------------
Phase v0.4 — Web feed (ROADMAP §0.4).
The scored items are now usable in a browser, and the app refreshes itself.

- web/app.py: FastAPI + HTMX feed bound to 127.0.0.1 only; GET / reads the scored
  items (core/items.read_feed) and renders them as cards grouped by day
  (published_at, fallback first_seen) with fresh days on top and descending score
  within a day. Each card shows title link, source, date, score, the top_node's
  Ukrainian label, and a feedback field that renders but posts nowhere (0.5).
- Clickable node-tag filter: GET /?node=<id> narrows the feed to that node; each
  card's tag links to its own filter and an "всі" link resets. Filtering lives in
  the card tags — no separate panel.
- APScheduler inside the process: a BackgroundScheduler started in the FastAPI
  lifespan runs the collect -> embed -> score pass every collection_interval_hours
  (4 default, from config), in a worker thread; one process, no separate worker.
- Dependencies added: fastapi, uvicorn, jinja2, apscheduler. 78 tests green, ruff
  clean; routes via the TestClient, the scheduler job with the pass mocked — no
  paid/network call in CI.

No new contracts. Translation and the language toggle are NOT here — they are
phases v0.8/v0.9 (MISSION decision 26).

Version 0.3.0 (2026-07-29)
---------------------------
Phase v0.3 — Scoring + CLI preview (ROADMAP §0.3).
Items now rank against the interest model.

- core/embeddings.py: Voyage client (voyage-3) over httpx — input_type=document
  for items, query for centroids; no LLM in the scoring path. Item vectors cached
  as float32 BLOBs in items.sqlite; only uncached rows are embedded.
- core/scoring.py: node centroids computed on the fly (no cache); the relevance
  gate on the PURE cosine (0.35, config) — weight ranks but never gates; score =
  max over eligible nodes (cosine × weight), argmax stored as top_node.
- core/pipeline.py: the collect -> embed -> score pass; backfill of the NULL
  embeddings left by 0.2; idempotent (a re-run re-scores from cache for free).
- CLI preview: python -m core.scoring --preview [--threshold X] prints the top-N
  by score with top_node/cosine, so the 0.35 gate is calibrated by eye.
- VOYAGE_API_KEY + the scoring threshold added to config. 66 tests green, ruff
  clean; all Voyage HTTP mocked, no paid/network call in CI.

Also in this release (tooling + planning, no runtime code): the run-phase skill
(chains generate -> upload -> execute for one phase); and a spec addition —
Ukrainian translation planned as phases v0.8 (backend) + v0.9 (feed toggle),
MISSION decision 26.

Contracts pinned this release: the embedder seam (voyage-3, document/query, key
from config, no LLM) and the cosine-only relevance gate, each with a contract test.

Version 0.2.0 (2026-07-29)
---------------------------
Phase v0.2 — Guardian collector + items.sqlite (ROADMAP §0.2).
Real articles now land on disk, deduplicated by URL.

- core/config.py: read-only config seam over stdlib tomllib; the Guardian key is
  read from the gitignored config.toml (fails loudly on a missing file/key).
  Committed config.example.toml documents the shape.
- core/items.py: the item store — items.sqlite (WAL) on the pinned 9-column
  schema (url PRIMARY KEY, source, title, summary, published_at, first_seen,
  embedding, score, top_node); Item class; upsert() dedups by URL, preserves
  first_seen, and leaves embedding/score/top_node NULL for phase 0.3.
- collectors/guardian.py: the first collector — one OR-joined Guardian request
  per node (free-tier budget), normalized into Item rows; run_collect() +
  `python -m collectors.guardian` fills items.sqlite and prints a
  fetched/new/deduped summary. No scheduler, no embeddings (phases 0.4 / 0.3).
- Dependency added: httpx. 40 tests green, ruff clean; all Guardian HTTP mocked,
  no paid/network call in CI.

Contracts pinned this release: the Item shape / items schema (contract test);
the config seam (tomllib read) introduced.

Version 0.1.0 (2026-07-05)
---------------------------
Phase v0.1 — Memory package + initial model.yaml (ROADMAP §0.1).
The interest model now exists on disk with an auditable origin.

- memory/model.yaml: the initial interest model — 14 reviewed topic nodes in the
  flat prototype format (id, label, keywords, weight); evidence/work metadata
  from the candidates dropped.
- core/model.py: Node reader and a ruamel round-trip weight writer that preserves
  the human's comments and formatting (pyyaml deliberately not used).
- core/events.py: append-only event journal in memory/events.sqlite (WAL) with
  the minimal, non-extensible schema (id, ts, kind, node_id, payload);
  kind ∈ {bootstrap, feedback, weight_update}.
- core/init_memory.py: writes one bootstrap provenance event tracing the model
  to the Lumi facts snapshot (2026-07-04, node_count=14); idempotent.
- Toolchain: pyproject with pytest + ruff. 21 tests green, ruff clean; all
  paid/network calls are mocked (none exist this phase).

Contracts pinned this release: the flat node format and the minimal events
schema, each with a contract test.
